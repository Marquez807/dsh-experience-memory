# 预注册：L1（每轮摘要）该厚还是薄

状态：**未执行**。判据先写在这里，再动手——因为上一次有人写下了"下一轮该做什么"，然后没人接着走
（`docs/DELIVERY-GAPS.md` §13.5 就是那样一段）。

## 一、要验的问题

现在每轮摘要里的一行是 `- [id] 标题 — lesson`：**行动指令直接写在摘要里**。另一种设计是摘要只给
**指针**（`- [id] 标题 — 讲的是什么`），要详情就用 `memory_recall` 的 `record_ids` 去取（0.5.8 才补上这条路）。

| | 支持"薄" | 支持"厚" |
|---|---|---|
| 依据 | L2 的预算 16384 字节**大量闲置**，而 L1 每行上限 240 字节、最多 5 条；详情里有边界、失败模式、出处——摘要里那句被截断的话，可能让人以为"照做就行" | 实测 **15,896 次真实调用里 `memory_recall` 只有 9 次**（`DELIVERY-GAPS.md` §12.6）。摘要薄了而 agent 不查，记忆就彻底静默 |
| 性质 | 结构上的浪费 | 行为上的实测 |

**两边都有依据，所以这件事不能靠推理定，要跑。**

## 二、两臂

| 臂 | L1 每行 | 行字节上限 | 固定提示 |
|---|---|---|---|
| **A（现状）** | `- [id] 标题 — lesson` | 240 | 现在的 `RECORD_HINT` |
| **B（薄）** | `- [id] 标题 — 讲的是什么`（去掉行动指令） | 120 | 改为：「摘要里列出的相关经验**先取全文再动手**（`memory_recall` 带 `record_ids`，全文含边界与出处）」 |

**常驻规矩层（`standing`）在两臂都保持厚**：它决定行为底线，不能指望"回头再查"。
其余全部相同：同一份库副本、同一批任务、同一模型、同一判据。

## 三、判据（跑完照此判，不事后改）

**过关必须同时满足三条**：

1. **B 臂的任务正确率 ≥ A 臂**——允许持平，不允许更低；
2. **B 臂的 `memory_recall` 调用次数 > 0**——否则说明薄 L1 被直接忽略，记忆静默失效；
3. **B 臂摘要覆盖的条数 ≥ A 臂**——薄的意义就在于同预算能列更多条。

**任一不满足 ⇒ 不做这个改动**，L1 保持现状（只保留已落地的 `record_ids` 通道）。

## 四、场景（不新造，用判别力已验证过的）

- **候选一**：`DELIVERY-GAPS.md` §19 那一对对照（0/12 vs 9/12，p=0.0003）；
- **候选二**：§22 那一对（0/6 → 6/6，p=0.0022）。

**执行前必须先确认**：该场景在"不给经验"那一臂**会失败**。否则测的是天花板——§23 的教训写得很清楚：
**天花板和地板都是"没有信息"**，两边都做对或两边都做错，都无法回答"经验有没有用"。

## 五、成本与做法

- 隔离环境：一次性 `DSH_HOME` + 一次性 profile + 库副本，沿用 `tools/standing-ab/` 与 `tools/t2-*` 的先例；
- **每臂 ≥ 8 次**——§11 的教训：3 组对照里的一次差异什么都证明不了；
- 判定**只看产物文件**，不看模型自述（§8 的教训：没有投递记录的回合里，模型的自我报告不是证据）；
- 判据不写进产物文件的那些观察，一律标"未验证"。

## 六、结果落点

- 原始数据：`tools/l1-ab/results.jsonl`（新目录，与 `standing-ab` 并列），含每回合的臂、产物、`memory_recall` 次数；
- 结论：**无论过不过都写**进 `docs/CONCLUSIONS.md`——过 = `成立`，不过 = `作废`，并在 `docs/CLAIMS.json` 登记状态与凭证；
- 作废的凭证就是上面那个 `results.jsonl`（必须留在仓库里，否则下一个会话只能重跑）。
