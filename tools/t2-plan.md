# T2 预先声明的判据、以及本轮对测试台做的修正

输出方：主工作区排障会话（2026-09-24 凌晨，用户指令"接着把 T2 剩下的 45 次跑完"）
接收方：记忆框架开发会话 / 用户

**这份文件的作用是"先声明、后跑"**：跑之前把判据和结论写死，跑完只填数字、不改口。凡是跑完
才改的口径，一律要在这份文件的「修正记录」里写明理由。

## 一、预先声明的结论表（原文照抄，来自 2026-09-23 18:36 的汇报）

> **跑完我按「结论先行表」填数字，不改口**：
>
> | 结果 | 结论 |
> |---|---|
> | 一致率 ≥80% 且 3 次一致 | 做 `effect` 字段；"效果量不出来"翻转 |
> | 60–80% | 只做候选 + 人判，不自动写 |
> | <60% | 不做；"成长型"要重新定义（没有反馈回路） |
> | 阴性对照被删成"必需" | **整体作废** |

**如实说明一处口径不一致**：上面这张表是照"删除测试（拿掉一条记录看结果变不变、再与人工判定比
一致率）"写的；而实际落地的 T2（`tools/t2-scenarios.json`）是**五臂预防设计**——四类真实教训
各一个任务，五个臂 = 不用经验 / 用对口经验 / 三条已知无关经验当对照，每组跑 3 次，只看产物不看
模型说什么。两者不是同一个量。

**所以本轮的读法（事先定死，不新增阈值）**：

1. **逐场景看方向**：对口经验臂（rel）显著好于"不用经验"（none）＝该场景支持"经验能防住这类错"。
2. **阴性对照是有效性的关键**：如果三条无关经验（ctrl1–3）表现得和 rel 一样好，或明显好于 none，
   说明"有效"是噪声或一般性提示导致的 ⇒ **按上表最后一行，整体作废**。
3. **不新造百分比阈值**。上表的 80/60 是对"与人工判定的一致率"说的，本设计里没有人工判定这个量，
   硬套等于跑完再编口径。四个场景的方向是否一致、对照是否阴性，就是本轮的结论依据。
4. 任一小格若标记 `timeout=true`，按"没做出来"记（判据只看产物），但会在表里单列，不混进"写错了"。

## 二、本轮对测试台做的修正（都在开跑前做完并实测，判据一个字没改）

| # | 改了什么 | 为什么（实测证据） |
|---|---|---|
| 1 | `t2-scenarios.json` 里 ctrl2 的标题：中文引号 `“”` → 英文引号 `""` | 库里那条记录存的是英文引号；标题对不上 ⇒ `t2-seed.mjs` exit 2 ⇒ 该臂**静默退化成"没有记忆"**。bom/ctrl2 旧数据（3 行）因此被污染，已移出并重跑 |
| 2 | `t2-run.ps1`：播种后**检查退出码**，失败就记 `seed-failed` 并中止这一格 | 没有这道检查时，"播种失败"与"库里本来没有记忆"在产物上完全一样，测出来的是假结论 |
| 3 | `t2-seed.mjs`：新增 `--title-file`；lib 改为从**本文件**解析而不是 `process.cwd()` | PowerShell 把参数交给原生程序时会重写引号，标题里的英文双引号被吃掉（实测 exit 2）；按 cwd 找库则换个目录调用就 `ERR_MODULE_NOT_FOUND` |
| 4 | `t2-run.ps1`：单次硬超时 **480 秒**（先声明），并记录 `timeout`/`seconds` | 没有超时的那版被一个挂住的回合拖死整轮（20:17 那次就没跑完）。实测：超时机制生效（一跑 482.1 秒被掐断） |
| 5 | `t2-run.ps1`：给隔离环境配**静态凭据存储**（`GIT_CONFIG_GLOBAL` 指向隔离配置） | stdin 场景依赖 `git credential fill`，而本机沙箱禁止 git 起凭据助手管道：实测**人手跑也必失败**（`cannot create standard input pipe for bash: Permission denied`）⇒ 四个臂会一起红，测的是环境不是记忆。修完实测 `git credential fill` 正常回显 |
| 6 | `t2-run.ps1` 一次性建环境那段的 `Remove-Item -Recurse` → `cmd /c rmdir` | 那条路径会穿过目录联接落到别处，PowerShell 5.1 的 `Remove-Item -Recurse` 会跟进联接、可能删到目标里去 |
| 7 | `t2-sweep.ps1`：**按格断点续跑**（有效的格子不重跑，占位行必须重跑） | 一轮可能跑几小时；中途被打断时不该重等（一个超时格子重跑就是白等 8 分钟） |
| 8 | 新增 `tools/t2-preflight.ps1`：开跑前一条命令回答"会不会白跑" | 上面 1/3/4/5 这些坑**都能在跑之前查出来**。教训是："已知的坑只写进文档、没变成流程里必跑的一步" |
| 9 | 单格超时从 `Wait-Process -Timeout` / `Wait-Job -Timeout` 改成**轮询**（`Get-Date` + `Start-Sleep` + `HasExited`） | 两层 `-Timeout` 在扫里都没生效：声明 480 秒，实际一格跑了 **26 分钟**；加了 720 秒外层看门狗后，一格又跑了 **13 分钟**，两层都没掐断。轮询版实测 6.5 秒掐断（预检门第 ⑥ 条自证） |
| 10 | 修 `tools/replay.mjs` 第 51 行的语法错误（缺一个换行，commit `32568de` 引入） | 交付说明里写着"想复核就跑它"，而它整个是 `SyntaxError`。修好后实测：投递率 **5.58%**、失败覆盖 2.94%、单记录最大误触发 **699** —— 文档里的 1.18% / 83 已不描述当前库。详见 `docs/DELIVERY-GAPS.md` §23.5 |
| 11 | 存量锚点回填跑一遍（只出提案）：`node tools/backfill-anchors.mjs --cwd F:\dsh主工作区` | **0 条候选**：能机械推的都已由 `recordAnchors(..., { derived: true })` 覆盖，剩下的静默记录缺的是**声明**。所以本轮把力气花在写新记录时提议锚点（`recall_for_suggestions`），而不是事后回填 |

**测试台自身的失效模式另有一份完整记录**：`docs/DELIVERY-GAPS.md` 第 23 节（23.1 上限不自证、
23.2 播种失败静默退化、23.3 引号被命令行吃掉、23.4 场景在本机不可能通过、23.5 复核命令坏了、
23.6 回填 0 条）。修完这些之后，本轮才有一个"数字可信"的测量环境。

**废数据留证**：本轮因上述缺陷产生、不计入结论的行，全部留在
`tools/t2-invalid-launchbug-20260923.jsonl`（12 行启动参数被空格拆开的空转行 + 3 行种子失败的占位行
+ 3 行被污染的 bom/ctrl2）。不计入结论，但也不静默删除。
